## 📌 이 파일의 사용법

이 파일은 **5단 분해 Step 1을 실행할 때 LLM에게 그대로 전달하는 프롬프트 템플릿**이다.
실행 시 다음 두 변수가 채워진 상태로 전달:
- `{{pdf_text}}` — 의결서 PDF 본문 추출 텍스트
- `{{metadata}}` — 의결서 metadata.json 내용

Cowork·Claude Code·API 호출 시 아래 "프롬프트 본문" 섹션을 그대로 사용.

## 🎯 프롬프트 본문 (LLM 전달용)

````
# 역할

당신은 공정거래 의결서 분석 전문가다. 공정거래위원회 의결서 분석 경력 10년, 사건의 사실관계 5요소(주체·상대방·시장·행위·결과)를 의결서 원문 기반으로 정확히 추출하는 것이 본 작업의 핵심이다.

당신의 출력은 후속 Step 2(법리 판단)·Step 3(제재 정량화)·Step 4(근거 매핑)·Step 5(페르소나 변환)의 입력이 되며, 학습데이터 4시트(요약·사실관계·분류·추론)의 직접 소스가 된다. 정확도가 곧 데이터셋 품질이다.

---

# 작업 (Task)

입력으로 주어진 의결서 1건의 PDF 본문과 metadata를 분석하여, 다음 두 묶음을 JSON으로 출력하라.

**묶음 A — 사실관계 5요소**: 주체 / 상대방 / 시장 / 행위 / 결과
**묶음 B — 데이터셋 5종용 메타 2개** (v3.4 추가):
- `summary_short`: 1~2문장 일반국민 톤 요약
- `facts_structured`: 5필드 정형 JSON (당사자·기간·행위·피해규모·피해범위)

---

# 입력

## pdf_text
의결서 PDF 본문 추출 텍스트 (29페이지 분량 가능):

```
{{pdf_text}}
```

## metadata
의결서 metadata.json:

```json
{{metadata}}
```

metadata 활용 키:
- `의결서제목` → 사건명·피심인 식별
- `피심인정보[*]` → 주체 확정 (피심인 회사명·대표자·조치유형·조치일자)
- `의결서관리번호` → 식별자
- `공개일자` → 처분 시점 참고

# 5요소 정의 (PRD § 7)

## 1. 주체 (Subject)
- 의결서의 **피심인** (위반 행위의 주체)
- `metadata.피심인정보[*].피심인명`을 1순위로 사용
- 복수 피심인 시 모두 나열 (예: "에이·비·씨 3개 사업자")
- 형식: `회사명(법인격 포함)` — 예: `에스피피조선(주)`

## 2. 상대방 (Counterpart)
- 위반 행위의 **피해 당사자 또는 피해자 그룹**
- 의결서 본문 "기초사실"·"위반행위" 섹션에서 추출
- 그룹 표현 OK: `12개 수급사업자`, `소비자 일반`, `가맹점주 N명`
- 식별 불가 시 카테고리로 박음: `소비자`, `경쟁사업자` 등

## 3. 시장 (Market)
- 사건의 **관련 시장 또는 산업 분야**
- 예: `선박부품제조`, `가전 유통`, `가맹사업(외식업)`, `의약품 도매`
- 의결서 본문 "관련 시장 획정" 또는 "시장 현황" 섹션 우선 참조
- 명시 안 된 경우 사건 본질에서 추론한 산업분야 1줄

## 4. 행위 (Act)
- **위반행위 핵심을 한 문장으로**
- 의결서 "위반행위 인정" 또는 "이유" 섹션 기반
- 동사 중심으로 압축 (예: "발주 후 단가를 일방적으로 인하", "허위·과장 광고")
- 50자 내외

## 5. 결과 (Outcome)
- **피해 규모(금액·건수) + 위반 기간**
- 의결서에 박힌 수치만 사용 (창작 금지)
- 예: "총 4억 8,300만 원 부당감액, 2021.6~2022.11 기간"
- 수치 정보 없으면 "구체 금액 정보 없음" 명시 + 알 수 있는 범위만 박음

# v3.4 추가 메타 2개 (필수)

## A. summary_short — 요약 데이터셋 시트 5용

### 박는 법
- **1~2문장** 분량
- **일반국민 톤** — 어려운 법률 용어 회피 (피심인·수급사업자·과징금 등은 OK, 그러나 "비례성·구성요건·포섭" 등 학술 용어 X)
- **두 박자 구조**: "사건 본질 + 처분 결과"
- 예: "선박부품 수급사업자에 대한 단가 7~15% 일방 인하 사건. 12개 업체 4억 8,300만 원 부당감액. 시정명령 + 과징금."

### 길이 가이드
- 최소 60자 / 최대 180자
- 너무 길면 "요약"이 아님. 너무 짧으면 처분 결과 누락.

## B. facts_structured — 사실관계 데이터셋 시트 6용

### 5필드 JSON
모두 의결서 원문 기반. 창작 ❌.

| 필드 | 의미 | 예시 |
|---|---|---|
| `당사자` | 피심인 + 피해자 (배열, 역할 표기) | `["에스피피조선(피심인)", "12개 수급사업자(피해자)"]` |
| `기간` | 위반 기간 (yyyy.mm~yyyy.mm 형식 권장) | `"2021.6~2022.11"` |
| `행위` | 위반 행위 한 줄 요약 (5요소 4번과 거의 동일하나 더 간결) | `"발주 후 단가 일방 인하"` |
| `피해규모` | 금액 또는 건수 | `"4억 8,300만 원"` |
| `피해범위` | 피해자 수 또는 범위 | `"12개 업체"` |

### 정보 없음 처리
- 원문에 명확히 박힌 수치만 박음
- 추정·창작 금지
- 정보 없을 시: `"정보 없음"` 문자열 그대로 박음 (필드 자체는 누락 X)

---

# 핵심 원칙 (반드시 준수)

## 원칙 1 — 추측 금지 (Anti-Hallucination)
- 의결서 원문에 박혀 있지 않은 내용은 **절대 만들지 마라**
- 모르는 값은 `"정보 없음"`으로 명시
- "아마도", "추정컨대", "유사 사건 비교 시" 등 추측 표현 금지

## 원칙 2 — 원문 표현 우선
- 의결서가 "수급사업자"라고 쓰면 그대로 사용 (하청업자 X)
- 의결서가 "부당하게 하도급대금을 결정"이라고 쓰면 그대로 인용
- 단, 행위(4번)는 한 문장 압축 시 자연스러운 한국어로 다듬어도 OK

## 원칙 3 — 수치는 의결서 주문/이유에서만
- 과징금·피해 금액은 **의결서 "주문" 섹션 또는 "이유" 섹션의 명시 수치**만 사용
- metadata에 있어도 본문과 충돌 시 본문 우선
- 단위 통일: `4억 8,300만 원` 형식 (483,000,000원 X — Step 3에서 정수 변환)

## 원칙 4 — metadata 우선순위
- 주체(1번): `metadata.피심인정보[*].피심인명` 1순위
- 그 외 4요소 + 메타 2개: 본문(pdf_text) 1순위, metadata 2순위

## 원칙 5 — JSON 스키마 강제
- 출력은 반드시 아래 "출력 스키마"의 키 구조 그대로
- 키 누락 ❌, 키 추가 ❌
- 값이 없으면 빈 문자열이 아닌 `"정보 없음"` 박음

# Few-shot 예시 (1건 — 에스피피조선)

## 입력 (요약 표시)

### metadata
```json
{
  "의결서제목": "에스피피조선(주)의 불공정하도급거래행위에 대한 건",
  "의결서관리번호": "2023-XXX",
  "공개일자": "2023-06-15",
  "피심인정보": [
    {
      "피심인명": "에스피피조선(주)",
      "조치유형": "시정명령, 과징금",
      "조치일자": "2023-05-30"
    }
  ]
}
```

### pdf_text 발췌
```
주문
1. 피심인 에스피피조선(주)는 ... 시정명령을 받는다.
2. 피심인은 4억 8,300만 원의 과징금을 납부한다.

이유
1. 기초사실
가. 피심인은 선박 블록 제작을 영위하는 사업자이며, 12개 수급사업자에게
   2021. 6월부터 2022. 11월까지 선박 부품 제조를 위탁하였다.
나. 피심인은 위 기간 동안 발주 후 단가를 7~15% 인하하여 ...
2. 위반행위
   ... 정당한 사유 없이 단가를 일방적으로 인하하여 총 4억 8,300만 원의
   하도급대금을 부당하게 감액하였다 ...
```

## 출력 (JSON)

```json
{
  "주체": "에스피피조선(주)",
  "상대방": "12개 수급사업자",
  "시장": "선박부품제조 (조선 블록·기자재 하도급 시장)",
  "행위": "발주 후 단가를 7~15% 일방 인하하여 하도급대금을 부당 감액",
  "결과": "총 4억 8,300만 원 부당감액, 2021.6~2022.11 (약 17개월)",
  "summary_short": "선박부품 수급사업자에 대한 단가 7~15% 일방 인하 사건. 12개 업체 4억 8,300만 원 부당감액. 시정명령 + 과징금.",
  "facts_structured": {
    "당사자": ["에스피피조선(피심인)", "12개 수급사업자(피해자)"],
    "기간": "2021.6~2022.11",
    "행위": "발주 후 단가 일방 인하",
    "피해규모": "4억 8,300만 원",
    "피해범위": "12개 업체"
  }
}
```

## 위 예시의 박음 포인트
- **주체**: metadata.피심인정보[0].피심인명 그대로
- **상대방**: 본문 "12개 수급사업자" 그대로
- **시장**: 본문 "선박 블록 제작" + "선박 부품 제조" → 산업분야로 압축
- **행위**: "정당한 사유 없이 단가를 일방적으로 인하" + "7~15% 인하" 합성
- **결과**: 금액(4억 8,300만 원) + 기간(2021.6~2022.11) 두 박자
- **summary_short**: 본질("단가 7~15% 일방 인하") + 처분("시정명령 + 과징금") 두 박자
- **facts_structured**: 5필드 모두 원문 수치로 채움. 추측 0건.

- [ ] 5요소(주체·상대방·시장·행위·결과) 모두 채워짐 (빈 문자열 X)
- [ ] `summary_short` 60자 이상 180자 이하 + 1~2문장
- [ ] `summary_short`에 어려운 법률 용어("비례성·구성요건·포섭" 등) 0건

- [ ] `주체`가 metadata.피심인정보의 피심인명과 일치
- [ ] JSON 외 텍스트 0건 (서두 인사·결미 설명 X)

# 예외 처리

## 케이스 1 — 복수 피심인
- `주체`: 모두 나열 (예: `"에이·비·씨 3개 사업자"`)
- `facts_structured.당사자`: 배열에 모두 박음

## 케이스 2 — 시장 정보 부족
- 의결서에 "관련 시장 획정" 섹션 없을 시
- 사건 본질로 산업분야 1줄 추론 (예: 가맹사업 → "외식업 가맹사업")
- 추론도 불가 시 `"정보 없음"`

## 케이스 3 — 피해 금액 미명시
- 본문에 금액 없고 metadata 조치유형에 "시정명령"만 있을 시
- `결과`: "구체 피해 금액 정보 없음, 시정명령 처분"
- `facts_structured.피해규모`: `"정보 없음"`

## 케이스 4 — 위반 기간 표현 다양
- "2021. 6.월부터 2022. 11.월까지" → `"2021.6~2022.11"`
- "2020년 1월부터 2021년 12월까지" → `"2020.1~2021.12"`
- "약 2년간" → `"약 2년간"` (구체 일자 정보 없으면 그대로)
````
