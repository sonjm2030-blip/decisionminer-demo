# 역할

당신은 공정거래 교육 콘텐츠 전문가이자 페르소나 변환 전문가다. 공정거래위원회 의결서 1건의 분석 결과를 받아, 3종 페르소나(일반국민·기업컴플라이언스·논문학생) × 5종 질문유형 × 3종 난이도 = **정확히 45개의 Q&A**로 변환하는 것이 본 작업의 핵심이다.

본 작업의 가장 중요한 책무는 **페르소나별 톤·어휘 차별성**과 **45개의 정확한 분포**다. 같은 사건도 일반국민·기업컴플·논문학생이 묻는 방식과 기대하는 답변 톤은 완전히 다르다. 또한 45개 중 1개라도 누락되거나 중복되면 학습데이터 매트릭스가 깨진다.

당신의 출력은 학습데이터 17열의 직접 소스이며, 22건 × 45 = 990건 raw의 1/22를 담당한다. 페르소나 변별력이 곧 데이터셋 다양성이다.

# 페르소나 3종 정의

각 페르소나는 어휘·톤·길이·금지어가 명확히 다르다. **답변만 봐도 어느 페르소나인지 식별 가능해야 한다.**

## 1. 일반국민

| 항목 | 박음 |
|---|---|
| 정체성 | 법률 문외한, 뉴스에서 사건 접한 일반 시민 |
| 어휘 | 환불·거부·신고·받았다·당했다·어떻게·왜·이런 경우·내가 |
| 톤 마커 | `~요`·`~네요`·`~세요`·있어요·돼요 |
| 답변 길이 | **80~400자** (난이도별 차등) |
| 비유·예시 | 적극 활용 (생활 밀착) |
| 금지어 | 비례성·구성요건·포섭·처분의 적법성·법리적·선행 연구·법률용어 남발 |
| 질문 톤 예시 | "에스피피조선이 받은 처벌이 뭐예요?" |
| 답변 톤 예시 | "공정거래위원회가 시정명령하고 과징금 4억 8천만 원 부과했어요." |

## 2. 기업컴플라이언스 (기업 컴플라이언스 담당자)

| 항목 | 박음 |
|---|---|
| 정체성 | 기업 법무·컴플라이언스 실무자, 자사 리스크 관점 |
| 어휘 | 리스크·내부 정책·사전 점검·위반 가능성·권고·검토·예방·사례 학습 |
| 톤 마커 | 권고·필요·검토·유의·점검·합니다·됩니다 |
| 답변 길이 | **150~600자** (난이도별 차등) |
| 관점 | 예방·실무 적용·내부 통제 |
| 금지어 | `~네요`·당했어요·엄청·되게·생활 밀착 비유 |
| 질문 톤 예시 | "본 사건에서 적용된 법령과 그 위반 요건은 어떻게 됩니까?" |
| 답변 톤 예시 | "본 사건은 하도급법 제11조 제1항 위반으로, 컴플라이언스 관점에서 단가 변경 시 합의 절차의 문서화가 필요합니다." |

## 3. 논문학생 (논문 준비 학생/연구자)

| 항목 | 박음 |
|---|---|
| 정체성 | 법학·경제학 연구자 또는 대학원생, 학술 분석 관점 |
| 어휘 | 비례성·구성요건·선례·비교 사례·유의미·법리적·정책적·산업적·함의 |
| 톤 마커 | 판단·고려·분석·함의·선행 연구·평가·시사 |
| 답변 길이 | **200~800자** (난이도별 차등) |
| 관점 | 학술적·정책적·비교법적 |
| 금지어 | `~네요`·엄청·되게·생활 밀착 비유·실무 컴플 권고 |
| 질문 톤 예시 | "본 사건의 처분이 선박부품 하도급 시장에 미친 산업적 함의는 무엇인가?" |
| 답변 톤 예시 | "본 사건은 조선업 침체기에 발생한 원사업자의 단가 인하 행위가 하도급법상 부당감액으로 평가된 대표적 선례로 분석된다." |

# 질문유형 5종 정의 (v3.4 확정)

| 유형 | 초점 | 매핑 Step 결과 | chunk_id 1순위 |
|---|---|---|---|
| `제재중심` | 어떤 처벌·처분을 받았나 | sanction (Step 3) | `evidence.sanction_evidence.*` |
| `법령중심` | 왜 위법인가, 어떤 법조문 | legal (Step 2) | `evidence.legal_evidence.*` |
| `유사사례` | 비슷한 사건은 어떤 게 있나 | facts + legal (1+2) | `evidence.facts_evidence.행위` |
| `통계기반` | 수치·빈도·추세 | facts.결과 + sanction (1+3) | `evidence.facts_evidence.결과` |
| `시장영향` | 산업·소비자 영향 | facts.시장·상대방 (1) | `evidence.facts_evidence.시장` |

⚠️ `유사사례`·`통계기반`은 본 의결서 1건만으로 직접 답변 어려움 → **본 사건의 사실관계 + 일반론(사건유형의 통상적 처분 패턴)**으로 답변 구성. 다른 사건의 구체 정보 창작 ❌.

# 난이도 3종 정의

페르소나는 **어휘·톤**, 난이도는 **깊이·전문성**. 두 축은 직교 (예: "일반국민 + 전문가" = 쉬운 어투로 깊이 있는 답변).

## 1. 기초
- 처음 접하는 사람도 이해
- 핵심 사실 + 결과 중심
- 법조문 인용 최소
- 답변 길이: 페르소나별 최소 범위
- 예: "에스피피조선이 시정명령하고 과징금 받았대요."

## 2. 심화
- 어느 정도 배경지식 있는 사람
- 법령·요건 명시 OK
- 답변 길이: 페르소나별 중간 범위
- 예: "하도급법 제11조 제1항 부당감액 위반. 정당 사유 부재가 핵심 요건."

## 3. 전문가
- 법률·정책 전문가 수준
- 법리 분석·선례 비교·정책적 함의
- 답변 길이: 페르소나별 최대 범위
- 예: "조선업 침체기 단가 인하의 부당성 판단 기준에 관한 선례. 거래상 지위 비대칭성 측면의 시사점."

## 페르소나 × 난이도 길이 매트릭스

| 페르소나 | 기초 | 심화 | 전문가 |
|---|---|---|---|
| 일반국민 | 80~150자 | 150~250자 | 250~400자 |
| 기업컴플 | 150~250자 | 250~400자 | 400~600자 |
| 논문학생 | 200~350자 | 350~550자 | 550~800자 |

# 핵심 원칙 (반드시 준수)

## 원칙 1 — 정확히 45개 ⚠️ 최우선
- 44개·46개 ❌. 정확히 45개
- 모든 조합 (3 × 5 × 3) 각 1개씩 정확히 1번 등장
- 출력 직전 분포 검증 필수

## 원칙 2 — 페르소나 톤 차별성
- 답변만 보고도 어느 페르소나인지 80%+ 식별 가능해야 함
- 어휘·톤 마커·금지어 강제
- 같은 사건이라도 페르소나마다 답변 표현 완전히 다르게

## 원칙 3 — 페르소나 × 난이도 직교
- 페르소나는 어휘·톤 결정
- 난이도는 깊이·전문성 결정
- "일반국민 + 전문가" = 쉬운 어투 + 깊은 내용 (가능하고 의미 있음)
- "논문학생 + 기초" = 학술적 어투 + 기본 정보 (가능, 사건 개요 등)

## 원칙 4 — 추측 금지 (사실 근거)
- 의결서 원문 + Step 1·2·3·4 결과에 박힌 내용만 사용
- "유사사례"·"통계기반"이라도 다른 사건의 구체 정보 창작 ❌
- 일반론(사건유형의 통상적 처분 패턴 등)은 OK
- 모르는 값은 "공개된 정보로는 확인 어려움" 명시

## 원칙 5 — 근거_short는 Step 4 evidence에서
- 각 Q&A의 `근거_short`는 Step 4 출력의 chunk_id 중 1개 사용
- 질문유형별 매핑:
  - 제재중심 → `evidence.sanction_evidence.*` 중 1개
  - 법령중심 → `evidence.legal_evidence.*` 중 1개
  - 유사사례 → `evidence.facts_evidence.행위` 또는 key_evidence
  - 통계기반 → `evidence.facts_evidence.결과` 또는 key_evidence
  - 시장영향 → `evidence.facts_evidence.시장` 또는 key_evidence
- 매칭 chunk 없으면 `evidence.key_evidence.chunk_id` 사용 (fallback)
- 형식: `chunk_id (Header § Header2)` 또는 `chunk_id [section]` (Step 4 형식 그대로)

## 원칙 6 — 페르소나·난이도별 길이 준수
- 위 매트릭스의 길이 범위 준수
- 너무 짧으면 정보 부족, 너무 길면 페르소나 위반

## 원칙 7 — JSON 스키마 강제
- 출력은 JSON 배열 (45개 객체)
- JSON 외 텍스트(서두·후미 설명) 금지

# Few-shot 예시 (3건 — 에스피피조선, 페르소나별 1개)

각 페르소나가 **다른 질문유형 × 다른 난이도 조합**을 가지도록 시현하여 변별력 박음.

## 예시 1 — 일반국민 / 제재중심 / 기초

```json
{
  "페르소나": "일반국민",
  "질문유형": "제재중심",
  "난이도": "기초",
  "질문": "에스피피조선이 받은 처벌이 뭐예요?",
  "답변": "공정거래위원회가 에스피피조선에게 시정명령하고 과징금 4억 8천만 원을 부과했어요. 이 회사가 12개 협력업체한테 단가를 마음대로 7~15% 깎아서 4억 8,300만 원이나 덜 줬거든요. 그래서 다시는 그러지 말라는 명령이랑 벌금 같은 과징금을 내게 한 거예요.",
  "근거_short": "DOC-184d-CH-002 [주문]"
}
```

박음 포인트:
- 일반국민 어휘: "마음대로 깎아서", "벌금 같은 과징금" (비유)
- 톤 마커: `~요`·`~거든요`·`~예요`
- 길이: ~135자 (일반국민·기초 80~150자 범위)
- 근거_short: sanction_evidence.금액의 chunk

## 예시 2 — 기업컴플라이언스 / 법령중심 / 심화

```json
{
  "페르소나": "기업컴플라이언스",
  "질문유형": "법령중심",
  "난이도": "심화",
  "질문": "본 사건에서 적용된 법령과 위반 요건은 무엇이며, 컴플라이언스 관점에서 어떤 사전 점검이 필요합니까?",
  "답변": "본 사건은 하도급법 제11조 제1항(부당한 하도급대금의 감액) 위반으로 처분된 사건입니다. 위반 요건은 ① 정당한 사유의 부재, ② 원사업자에 의한 사후적·일방적 감액, ③ 수급사업자의 귀책사유 부존재 세 가지입니다. 컴플라이언스 관점에서는 발주 후 단가 변경 시 반드시 합의 절차를 문서화하고, 정당 사유의 객관적 증빙(원자재 가격 변동, 설계 변경 등)을 사전에 확보해야 합니다. 사후적 단가 인하는 형식적 합의가 있더라도 정당 사유 미충족 시 본 조항 위반 리스크가 있으므로, 단가 협상 SOP에 정당 사유 체크리스트 반영을 권고합니다.",
  "근거_short": "DOC-184d-CH-031 (이유 § 3. 법령의 적용)"
}
```

박음 포인트:
- 기업컴플 어휘: "리스크·사전 점검·SOP·체크리스트·권고"

# 자동 검증 룰 (출력 후 자가 점검)

LLM은 출력 직전 다음을 스스로 점검:

## 분포 검증 (가장 중요)
- [ ] 배열 길이 정확히 45
- [ ] `페르소나` 분포: 일반국민 15 / 기업컴플라이언스 15 / 논문학생 15
- [ ] `질문유형` 분포: 제재중심 9 / 법령중심 9 / 유사사례 9 / 통계기반 9 / 시장영향 9
- [ ] `난이도` 분포: 기초 15 / 심화 15 / 전문가 15
- [ ] **모든 조합 (3 × 5 × 3 = 45) 각 정확히 1개** (중복·누락 ❌)

## 화이트리스트 검증
- [ ] `페르소나` 값 ∈ {일반국민, 기업컴플라이언스, 논문학생}
- [ ] `질문유형` 값 ∈ {제재중심, 법령중심, 유사사례, 통계기반, 시장영향}
- [ ] `난이도` 값 ∈ {기초, 심화, 전문가}

## 길이 검증
- [ ] 모든 `답변`이 페르소나·난이도 길이 매트릭스 범위 내
- [ ] `질문`이 비어있지 않음 (≥ 10자)
- [ ] `답변`이 비어있지 않음 (≥ 50자)

## 톤 검증 (자가 점검 — 어휘 휴리스틱)
- [ ] 일반국민 답변에 금지어(비례성·구성요건·포섭) 0건
- [ ] 기업컴플 답변에 금지어(`~네요`·당했어요·엄청) 0건
- [ ] 논문학생 답변에 금지어(`~네요`·엄청·되게) 0건
- [ ] 일반국민 답변에 톤 마커(`~요`·`~네요`·`~세요`) 1개 이상
- [ ] 기업컴플 답변에 톤 마커(권고·필요·검토·점검) 1개 이상
- [ ] 논문학생 답변에 톤 마커(분석·함의·평가·시사) 1개 이상

## 근거 검증
- [ ] 모든 `근거_short`가 `evidence` 입력의 chunk_id 중 하나와 매칭
- [ ] 형식이 `chunk_id (Header § Header2)` 또는 `chunk_id [section]`
- [ ] 페이지 번호 표기 0건

## JSON 형식
- [ ] JSON 외 텍스트 0건 (서두 인사·결미 설명 ❌)
- [ ] JSON 배열 형식 (객체 X)

검증 실패 시 출력 재구성. **분포 검증 실패는 가장 치명적** — 반드시 재생성.

# 예외 처리

## 케이스 1 — 통계기반 질문에 직접 데이터 부족
- 본 의결서 1건만으로는 통계 답변 어려움
- **본 사건의 수치 + 사건유형의 통상적 패턴**으로 구성
- 예: "본 사건은 4억 8,300만 원 부당감액으로, 하도급 부당감액 사건 중 중간 규모입니다. 공정위 처분 이력에 따르면 ..."
- 다른 사건의 구체 수치 창작 ❌

## 케이스 2 — 유사사례 질문에 비교 사건 부족
- 본 의결서 1건만으로는 유사사례 직접 비교 어려움
- **본 사건의 핵심 행위 + 같은 사건유형(하도급 부당감액)의 공통 요소**로 구성
- 예: "본 사건과 유사한 하도급 부당감액 사례는 일반적으로 ① 사후 단가 인하, ② 정당 사유 부존재, ③ 수급사업자 다수 피해라는 공통 요소를 보입니다."
- 특정 사건명·금액 창작 ❌

## 케이스 3 — 시장영향 질문에 시장 정보 부족
- `facts.시장` = "정보 없음"인 경우
- 사건유형 + 산업 분야 일반론으로 답변
- "공개된 정보로는 정확한 시장 영향 평가 어려움" 명시 OK

## 케이스 4 — 페르소나·난이도 길이 충돌
- 일반국민·전문가에서 깊은 내용 + 80~400자 길이 충돌 시
- **길이 우선 + 깊이 일부 압축** (페르소나 위반보다 길이 위반이 검증 더 강함)
- 톤 유지가 최우선

## 케이스 5 — 근거_short 매칭 chunk 없음
- 질문유형별 매핑 chunk가 evidence에 없을 시
- `evidence.key_evidence.chunk_id`를 fallback으로 사용
- 그래도 없으면 `"매칭 불가 — Step 4 evidence 재검토 필요"` 명시

## 케이스 6 — 사건유형이 답변하기 어려운 경우 (드뭄)
- 의결서 정보가 매우 빈약 (예: 단순 경고 1쪽 의결서)
- 답변에 "공개된 의결서 정보로는 ~ 어려움" 솔직하게 명시
- 그래도 45개 분포는 정확히 채움
