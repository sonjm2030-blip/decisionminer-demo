````
# 법령 화이트리스트 (7종 — 정확 인용 강제)

LLM은 **반드시 아래 7개 법령 약칭 중 하나만** `법령` 필드에 사용한다. 그 외 법령명(자본시장법·공정채권법·소비자기본법 등)은 사용 금지.

| 약칭 (출력값) | 정식 명칭 | 주요 사건 유형 |
|---|---|---|
| `공정거래법` | 독점규제 및 공정거래에 관한 법률 | 담합·거래상지위·부당지원·재판매가격·거래강제·부당고객유인·사업자단체 |
| `하도급법` | 하도급거래 공정화에 관한 법률 | 하도급 (대금 결정·감액·지급지연 등) |
| `전자상거래법` | 전자상거래 등에서의 소비자보호에 관한 법률 | 전자상거래 (청약철회·환불·표시광고) |
| `표시광고법` | 표시·광고의 공정화에 관한 법률 | 표시광고 (허위·과장·기만 광고) |
| `가맹사업법` | 가맹사업거래의 공정화에 관한 법률 | 가맹사업 (정보공개서·가맹금·계약갱신) |
| `대규모유통업법` | 대규모유통업에서의 거래 공정화에 관한 법률 | 대형 유통업체의 납품업체 거래 |
| `대리점법` | 대리점거래의 공정화에 관한 법률 | 대리점 (계약·반품·판매목표 강제) |

## 법령 식별 우선순위
1. 의결서 본문 "법령의 적용" 또는 "주문" 섹션에 명시된 법령명 → 그대로 약칭으로 변환
2. 본문에 정식 명칭으로 박힌 경우 → 위 표의 약칭으로 매핑
3. 두 곳에 모두 없을 시 → metadata 의결서제목 + facts.행위로 추론
4. 그래도 불명확 시 → `"식별 불가"` 명시 (절대 임의 추측 X)

# 4요소 정의

## 1. 법령 (Applied Law)
- **위 화이트리스트 7개 약칭 중 1개**
- 복수 법령 위반 시: 주된 법령 1개 + `judgment_requirements`에 부가 법령 명시
- 예: `"하도급법"`, `"공정거래법"`

## 2. 조문 (Applied Article)
- **`제N조` 형식 강제**. 항·호 있으면 함께 (`제11조 제1항`, `제45조 제1항 제6호`)
- 의결서 원문 표기 그대로 (예: "법 제11조제1항" → `"제11조 제1항"`로 정규화)
- 복수 조문 위반 시 주된 조문 1개

## 3. 위반유형 (Violation Type)
- 위반 행위의 **법적 분류명** (사실 행위가 아닌 법리상 명칭)
- 예: `"부당한 하도급대금의 감액"`, `"부당한 공동행위"`, `"기만적인 광고"`, `"거래상 지위의 남용"`
- 의결서 "위반행위 인정" 섹션의 법적 분류명 1순위
- 30자 내외

## 4. 판단요건 (Judgment Requirements)
- 위반으로 판단한 **핵심 법리적 요건 2~4개** (배열)
- 의결서 "이유" 섹션의 법리 분석에서 추출
- 일반론(법령 그 자체)이 아닌 **본 사건에 적용된 구체 요건**으로 박음
- 예: `["정당한 사유가 없을 것", "사후적·일방적 단가 인하일 것", "수급사업자가 책임질 사유가 없을 것"]`

# v3.4 추가 메타 2개 (필수)

## A. classification_tags — 분류 데이터셋 시트 7용

### 5필드 JSON

| 필드 | 의미 | 값 제약 |
|---|---|---|
| `사건유형_대분류` | 12종 중 1개 | **아래 12종 화이트리스트 강제** |
| `사건유형_세분류` | 구체 행위 분류 | 자유 텍스트 (10~30자) |
| `위반_조문` | 법령 + 조문 통합 표기 | `"<법령 약칭> <조문>"` 형식 |
| `처분_유형` | 처분 종류 (배열) | **아래 처분 유형 화이트리스트 강제** |
| `산업분야` | 사건의 산업 분야 | 자유 텍스트 (`시장` 필드와 정합) |

### 사건유형_대분류 화이트리스트 (12종 — 정확 매칭 강제)

```
담합 | 하도급 | 거래상지위 | 표시광고 | 전자상거래 |
사업자단체 | 가맹사업 | 부당고객유인 | 부당지원 |
재판매가격 | 거래강제 | 기타
```

분류 가이드:
- `담합` → 공정거래법 제40조 (부당한 공동행위)
- `하도급` → 하도급법 전반
- `거래상지위` → 공정거래법 제45조 제1항 제6호
- `표시광고` → 표시광고법 + 전자상거래법 표시광고 부분
- `전자상거래` → 전자상거래법 (청약철회·환불·표시 외)
- `사업자단체` → 공정거래법 제51조
- `가맹사업` → 가맹사업법
- `부당고객유인` → 공정거래법 제45조 제1항 제4호
- `부당지원` → 공정거래법 제45조 제1항 제9호
- `재판매가격` → 공정거래법 제46조
- `거래강제` → 공정거래법 제45조 제1항 제5호
- `기타` → 대규모유통업법·대리점법 등 위 11종에 명확히 들어가지 않을 때

### 처분_유형 화이트리스트 (배열, 복수 가능)

```
시정명령 | 과징금 | 고발 | 경고 | 시정권고 | 자진시정 종결 | 기타
```

배열 예시:
- `["시정명령", "과징금"]` (가장 흔한 조합)
- `["시정명령", "과징금", "고발"]` (중대 사건)
- `["경고"]` (경미한 사건)

`metadata.피심인정보[*].조치유형`을 1순위 참조. 본문 "주문" 섹션과 교차 검증.

### 산업분야
- Step 1의 `시장` 또는 `facts_structured.당사자` 정보와 정합
- 예: `"선박부품제조"`, `"가전 유통"`, `"외식업 가맹"`, `"의약품 제조·유통"`, `"건설업"`, `"통신서비스"`
- 식별 어려우면 `"식별 불가"` 명시

## B. inference_chain — 추론 데이터셋 시트 8용

### 4단계 구조 (배열, 정확히 4개 객체)

법리 추론을 **3단 논법 + 1 근거** 구조로 분해:

| 단계 | 키 | 의미 |
|---|---|---|
| 1 | `전제` | 일반 법리 전제 (법령이 정한 일반 규범) |
| 2 | `전제` | 본 사건의 사실 전제 (사실관계가 일반 법리에 포섭) |
| 3 | `결론` | 위반 결론 (어느 법령 어느 조문 위반인지) |
| 4 | `근거` | 의결서 식별자 (공정거래위원회 의결 + 의결서관리번호) |

### JSON 구조 (정확히 이 형식)

```json
[
  {"단계": 1, "전제": "<일반 법리>"},
  {"단계": 2, "전제": "<본 사건 사실 포섭>"},
  {"단계": 3, "결론": "<법령 + 조문 + 위반>"},
  {"단계": 4, "근거": "공정거래위원회 의결 <의결서관리번호>"}
]
```

### 박는 법
- **단계 1 (일반 법리)**: 의결서 "법령의 적용" 또는 "이유"에서 인용된 법령 일반 규범
  - 예: "하도급계약 체결 후 하도급대금은 정당한 사유 없이 감액할 수 없음 (하도급법 제11조 제1항)"
- **단계 2 (사실 포섭)**: Step 1의 facts와 의결서 인정사실의 핵심을 한 줄로
  - 예: "피심인은 12개 수급사업자에게 정당한 사유 없이 단가를 7~15% 일방 인하하여 4억 8,300만 원 감액 (의결서 인정사실)"
- **단계 3 (결론)**: 법령 + 조문 + "위반"
  - 예: "하도급법 제11조 제1항 위반"
- **단계 4 (근거)**: `metadata.의결서관리번호` 직접 박음
  - 예: "공정거래위원회 의결 2023-XXX"
  - metadata에 의결서관리번호 없으면 "공정거래위원회 의결 (관리번호 정보 없음)"

# 핵심 원칙 (반드시 준수)

## 원칙 1 — 법령 화이트리스트 강제
- 7개 법령 약칭 외 사용 금지
- 정식 명칭으로 박혀 있으면 약칭으로 변환 (예: "독점규제 및 공정거래에 관한 법률" → `"공정거래법"`)
- 화이트리스트 외 법령이 의결서에 등장하면 → `judgment_requirements`에 부가 정보로만 박고, `법령` 필드엔 주된 7종 중 1개만

## 원칙 2 — 조문 정확 인용
- 의결서 원문의 조문 번호 그대로 (창작 ❌)
- 형식 정규화만 허용: `"법 제11조제1항"` → `"제11조 제1항"`
- 의결서에 조문 번호 명시 안 된 경우 → `"제N조 정보 없음"` (절대 추측 X)

## 원칙 3 — 추측 금지
- 의결서에 박혀 있지 않은 법리·조문은 절대 만들지 마라
- "유사 사건에서는 통상 ~조 적용" 같은 일반화 X
- 모르는 값은 `"정보 없음"` 명시

## 원칙 4 — Step 1 결과 활용
- `facts.주체`·`facts.상대방`·`facts.행위` 정합성 유지
- `inference_chain` 단계 2(사실 포섭)는 Step 1 결과 기반
- `classification_tags.산업분야`는 `facts.시장`과 충돌 X

## 원칙 5 — JSON 스키마 강제
- 출력은 반드시 아래 "출력 스키마"의 키 구조 그대로
- `inference_chain`은 **정확히 4개 객체** 배열
- `classification_tags.사건유형_대분류` 12종 화이트리스트 외 값 ❌

# Few-shot 예시 (1건 — 에스피피조선)

## 입력 (요약 표시)

### metadata
```json
{
  "의결서제목": "에스피피조선(주)의 불공정하도급거래행위에 대한 건",
  "의결서관리번호": "2023-XXX",
  "피심인정보": [
    {
      "피심인명": "에스피피조선(주)",
      "조치유형": "시정명령, 과징금"
    }
  ]
}
```

### facts (Step 1 결과)
```json
{
  "주체": "에스피피조선(주)",
  "상대방": "12개 수급사업자",
  "시장": "선박부품제조 (조선 블록·기자재 하도급 시장)",
  "행위": "발주 후 단가를 7~15% 일방 인하하여 하도급대금을 부당 감액",
  "결과": "총 4억 8,300만 원 부당감액, 2021.6~2022.11 (약 17개월)"
}
```

### pdf_text 발췌
```
이유
2. 위반행위
   ... 정당한 사유 없이 단가를 일방적으로 인하하여 총 4억 8,300만 원의
   하도급대금을 부당하게 감액하였다 ...

3. 법령의 적용
   가. 하도급법 제11조 제1항
       원사업자는 ... 정당한 사유 없이 하도급대금을 감액해서는 아니 된다.
   나. 본건 적용

## 위 예시의 박음 포인트
- **법령**: 본문 "하도급법 제11조 제1항" 명시 → 약칭 `"하도급법"`
- **조문**: `"법 제11조제1항"` → `"제11조 제1항"` 정규화
- **위반유형**: 하도급법 제11조의 법적 분류명 (`"부당한 하도급대금의 감액"`)
- **판단요건**: 의결서 "법령의 적용" + 일반 법리에서 본 사건 적용 요건 3개 추출
- **classification_tags**:
  - 대분류: `하도급` (12종 중 1개)
  - 세분류: 본 사건의 구체 행위 분류
  - 처분_유형: metadata.조치유형 + 본문 주문 교차 검증
  - 산업분야: `facts.시장`과 정합
- **inference_chain**: 단계 1(일반 법리) → 단계 2(사실 포섭) → 단계 3(결론) → 단계 4(의결서 근거)

# 자동 검증 룰 (출력 후 자가 점검)

LLM은 출력 직전 다음을 스스로 점검:

- [ ] `법령` 값이 7개 화이트리스트 중 정확히 1개와 일치
- [ ] `조문` 값이 `제N조` 패턴 (정규식: `^제\d+조`)
- [ ] `판단요건` 배열 길이 2~4개
- [ ] `classification_tags.사건유형_대분류`가 12종 화이트리스트 중 정확히 1개
- [ ] `classification_tags.처분_유형` 배열의 모든 값이 처분 유형 화이트리스트 안에 있음
- [ ] `classification_tags.위반_조문`이 `법령` + `조문`과 정합 (예: `법령="하도급법"` + `조문="제11조 제1항"` → `위반_조문="하도급법 제11조 제1항"`)
- [ ] `inference_chain` 배열 길이 정확히 4
- [ ] `inference_chain[3].근거`에 의결서관리번호 또는 "관리번호 정보 없음" 박힘
- [ ] 모든 법령·조문·수치가 의결서 원문에서 추출 (창작 0건)
- [ ] JSON 외 텍스트 0건

# 예외 처리

## 케이스 1 — 복수 법령 위반
- 주된 법령 1개를 `법령` 필드에 박음 (의결서 "주문"의 1차 적용 법령)
- 부가 법령은 `판단요건`에 풀어 쓰거나 `inference_chain.단계 3` 결론에 병기
- `classification_tags.위반_조문`에 주된 조문만

## 케이스 2 — 조문 번호 불명확
- 의결서가 "관련 법령에 따라" 같은 일반 표현만 쓸 때
- `조문`: `"제N조 정보 없음"` 명시
- `inference_chain.단계 1`에 일반 법리만 박고 조문 추측 X

## 케이스 3 — 사건유형 12종 분류 모호
- 복합 위반 (예: 거래상지위 + 부당고객유인) → 의결서 "주문"의 1차 위반행위 기준
- 12종에 명확히 안 들어가는 경우 → `"기타"` + `사건유형_세분류`에 구체 분류 박음

## 케이스 4 — metadata.의결서관리번호 누락
- `inference_chain.단계 4`: `"공정거래위원회 의결 (관리번호 정보 없음)"` 그대로 박음
- 의결서 본문 표지에 사건번호(예: "공정위 2023의결-XXX") 보이면 그것을 박음

## 케이스 5 — 처분 유형이 화이트리스트에 없음
- 이례적 처분 (예: 동의의결, 기각) 발견 시
- `처분_유형` 배열에 `"기타"` + 정확한 처분명을 `판단요건` 또는 별도 메모로
````
