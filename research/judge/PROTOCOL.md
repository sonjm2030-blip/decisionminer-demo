# 공통 검수 기준을 적용한 LLM Judge 비교

이 실험은 기존 사람 검수 기록을 이용한 개발 실험입니다. 기존 판정을 바꾸거나 새 전문가 정답을 확정하는 절차가 아닙니다. 재검수 준비물을 추가로 변경하거나 전문가에게 의뢰하지 않습니다.

## 비교 대상과 입력

기존 검수표와 master의 공통 6항목이 일치하는 79건·16개 사건을 사용합니다. 이는 앞선 분석자가 이미 확인한 표본이며, 새로 나눈 시험세트가 아닙니다. 21건은 입력 대응 차이 때문에 제외한 상태를 유지합니다.

각 입력은 질문·답변·페르소나·사건유형·질문유형·난이도·법령·조문·사건명과 원문 PDF 발췌로 구성합니다. 검수자 판정·신뢰도·판단요건·본건 적용 이유·메모·보정안·최종 정적 라벨을 모델에 주지 않습니다. 모델 요청 번호도 기존 검수 ID와 다른 J001~J079를 사용합니다. 원문 발췌에는 사람이 제안한 보정 내용을 섞지 않습니다.

같은 사건의 원문 PDF 안에서 어휘·한국어 2글자 조합을 이용해 BM25 방식으로 검색합니다. 주문 부분의 청크를 최대 4개 우선 포함하고, 질문·답변·법령·조문으로 검색한 청크를 더해 최대 11개·10,500자를 제공합니다. 각 청크는 원문 PDF의 뷰어 쪽수와 식별자를 갖습니다. 전체 원문을 읽힌 실험은 아니므로 검색 누락과 원문 미포함 부분을 거짓으로 해석하지 않게 합니다.

두 방식은 문항별로 **완전히 같은 발췌와 출력 형식**을 사용합니다. 이전 규칙 검사와 비교할 때는 근거 문맥까지 달라지므로, 그 차이를 순수한 모델 효과로 해석하지 않습니다.

## 두 가지 검수 지시

- 단순 검수: [generic.txt](generic.txt). 질문에 정확하고 충분한 답변인지 확인하도록 요청합니다.
- 항목별 검수: [rubric.txt](rubric.txt). 사실, 법령, 적용과 결론, 처분·수치, 근거 범위, 질문 적합성·심각도를 구분합니다.

공통 판정 기준과 근거 인용 조건은 [common.txt](common.txt), 기록 형식은 [schema.json](schema.json)에 있습니다. 정책적 함의를 묻는 질문에서 해석·제안 자체를 오류로 처리하지 않고, 쉬운 설명에 모든 부수 절차를 요구하지 않도록 했습니다. 개별 문항의 정답이나 기존 메모를 프롬프트에 넣지 않습니다.

KCL의 근거·평가 기준 연결과 기존 검수 메모를 참고한 공통 기준입니다. 문항별 전문가 확정 루브릭이나 해당 논문의 재현 구현은 아닙니다. 관련 논문의 본문 대조는 [기존 분석 보고서](../legacy_review/README.md#7-기존-논문-본문의-방법과-대조)를 참고합니다.

## 실행 설정과 결과 보존

저장소의 기존 모델 설정과 연결되는 `claude-sonnet-4-6` 한 종류를 사용합니다. 온도 0, thinking 비활성화, 최대 출력 1,800토큰, 요청당 자동 재시도 0회입니다. 문항마다 두 방식의 요청 순서를 번갈아 배치하고 최대 4개씩 동시에 실행합니다. 첫 6건은 출력·연결 점검 후 같은 요청 결과를 재사용하므로 최종 실험에 중복 호출하지 않습니다. 결과를 보고 더 좋은 응답이 나올 때까지 재시도하지 않습니다.

모델과 SDK 버전, 프롬프트·출력 형식·실행 코드·모든 입력의 해시, 실제 모델 응답, 토큰 사용량과 지연시간을 기록합니다. 같은 실행 폴더에 다른 설정을 덮어쓰지 않습니다. 실패·잘못된 출력도 삭제하지 않습니다. 온도 0이 완전한 재현성을 보장한다는 주장은 하지 않으며 반복 실행의 변동성은 이번 범위에 포함하지 않았습니다.

모든 유료 호출 전에 토큰 수를 확인하고, 입력 수와 최대 출력 토큰을 합한 추정 상한이 12달러를 넘으면 새 모델 호출을 시작하지 않습니다. 비용은 공식 문서의 Sonnet 4.6 입력 100만 토큰당 3달러·출력 15달러를 기준으로 계산합니다. 이는 사용 토큰에 따른 추정이며 청구서 금액이 아닙니다. [Anthropic 모델·가격 문서](https://platform.claude.com/docs/en/models/sonnet-4-6/overview), 2026-11-01 확인.

## 출력 검증과 평가

검토·부적합 판정에는 문제 설명과 출처 인용이 필요합니다. 인용 청크가 실제 입력에 있고, 인용문이 해당 청크에 존재하는지 NFC 정규화·공백 제거 후 검사합니다. 검사 코드는 공백 제외 8자 이상을 요구합니다. 인용문의 법률적 함의까지 검증하는 것은 아닙니다. 원문 위치 오류, 요약을 인용처럼 적은 경우 등도 인용 검사에서 실패할 수 있습니다. 출력 형식 실패에는 요약 길이 초과도 포함되므로 법률적 오류 수로 해석하지 않습니다.

형식·인용 실패는 별도 `출력검증실패`로 남기며, 모델이 명시한 `판단보류`와 구분합니다. 원출력 판정을 삭제하지 않되, 검증 실패 응답을 정상 판정으로 성능 계산하지 않습니다.

결과에는 다음을 함께 기록합니다.

1. 전체 79건 중 기존 사람 판정과 같은 확정 판정 수, 확정 판정 비율, 판단보류·검증 실패 수.
2. 각 방식에서 판정이 완료된 부분의 세 범주 일치·범주별 혼동행렬·균형 정확도·Macro F1·κ. 부분 집합마다 분모와 구성도 제공합니다.
3. 두 방식 모두 확정 판정을 내린 공통 부분의 비교와 전체 79건에서 어느 방식만 기존 판정과 일치했는지.
4. 원문 인용이 맞아도 사람 판정과 다를 수 있으며, 사람 기록의 오류 가능성도 남아 있다는 한계.

판단보류·잘못된 응답을 조용히 버리고 높은 일치율만 제시하지 않습니다. 희소한 기존 환각 판정이 79건 중 1건뿐이므로 환각 탐지의 일반적 성능을 주장하지 않습니다. 한 모델·한 번의 생성만 사용하고 다른 제공자·모델군이나 전문가 간 비교는 수행하지 않습니다.

## 규칙과 결합하는 방식

사후 시뮬레이션에서는 기존 규칙이 검토·부적합으로 표시한 항목을 모델이 통과시키지 못하게 합니다. 규칙이 적합으로 통과한 43건만 모델에 확인시키며, 모델도 정상 출력으로 적합을 선택한 경우에만 통과 후보로 남깁니다. 검토·부적합·판단보류·검증 실패는 모두 사람 확인 대상으로 보냅니다. 이는 문항이 법적으로 틀렸다는 확정 판정이 아닙니다.

기존 보정 필요 중 추가로 잡는 수와 기존 OK 중 불필요하게 검토로 보내는 수를 함께 보고합니다. 같은 79건의 응답을 재사용한 시뮬레이션이며 실제 운영 검수나 원본 라벨 변경이 아닙니다. 실제 호출 비용은 측정하지만 사람 검수 시간·인건비·다운스트림 학습 효과는 측정하지 않습니다.

검수 순서도 규칙 경고, 항목별 모델 판정, 두 지시의 불일치로 사후 탐색합니다. 동점은 균등 선택의 기대값과 가능한 범위를 보고합니다. 두 프롬프트의 불일치는 같은 모델의 두 지시 결과로, 확률적으로 보정된 불확실성이나 CoAnnotating의 엔트로피 방법 재현으로 부르지 않습니다.
