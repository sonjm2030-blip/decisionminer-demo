# 기존 검수 기록과 LLM Judge의 첫 비교

2026-11-01 · 실제 API 실험 완료. 기존 입력 일치 79건·16개 사건에 단순 검수와 항목별 검수를 각각 실행했습니다. 기존 사람 판정과 메모·보정안은 모델 입력에 포함하지 않았습니다.

**이번 실험에서는 항목별 기준이 단순 지시보다 낫다는 근거를 얻지 못했습니다.** 모델의 형식·인용 신뢰성 문제가 컸고, 검토 대상을 넓히면 기존 OK 문항에 대한 추가 검토도 늘었습니다. 연구용 비교 코드·출력 검증·검수 대상 분류까지 구현했으며 공모전 원본과 생산 라벨은 유지했습니다.

## 1. 무엇을 실제로 실행했는가

| 항목 | 설정·실행 결과 |
| --- | --- |
| 문항 | 기존 검수와 공통 6항목이 일치하는 79건, 16개 사건 |
| 모델 | Claude Sonnet 4.6 (`claude-sonnet-4-6`) |
| 비교 | 단순 지시와 공통 항목별 지시, 각 79회 |
| 원문 | 같은 문항에는 두 방식 모두 동일한 의결서 발췌 제공 |
| 모델에 제공하지 않은 정보 | 사람 판정·신뢰도·판단요건·본건 적용 이유·메모·보정안·최종 라벨 |
| 실제 모델 응답 | 158개, 자동 재시도 없음 |
| 출력 형식·인용 검사 통과 | 116개. 이 중 확정 판정 113개, 판단보류 3개 |
| 출력 검사 실패 | 42개 |
| API·연결 실패 | 0개 |
| 사용 토큰으로 계산한 비용 | 약 **6.82달러**, 청구서 금액은 아님 |

기존 메모를 바탕으로 사실·법령·법 적용·처분과 수치·근거 범위·질문 적합성을 구분한 [공통 기준](rubric.txt)을 작성했습니다. 개별 문항의 정답을 프롬프트에 넣거나 모델을 학습시키지 않았습니다. 이것은 전문가 확정 루브릭이 아닙니다.

원문을 전부 넣은 실험은 아닙니다. 사건별 PDF에서 주문과 검색된 발췌를 최대 11개 제공했고, 자료 부족 시 판단보류를 허용했습니다. 구체적인 입력 구성·평가·실행 설정은 [실험 절차](PROTOCOL.md)에 있습니다.

## 2. 기존 판정과 얼마나 일치했는가

‘전체에서 같은 판정’은 확정 판정과 기존 사람 판정이 같은 건수를 전체 79건으로 나눈 값입니다. 판단보류나 출력 검증 실패를 정답으로 세지 않으며, 이를 법률적 오답으로 새로 확정하는 것도 아닙니다.

| 방식 | 확정 판정 가능 | 판단보류 | 출력 검증 실패 | 전체에서 기존 판정과 같은 확정 판정 |
| --- | ---: | ---: | ---: | ---: |
| 기존 구조화 규칙 | 79 | 0 | 0 | 43/79 (54.4%) |
| 단순 LLM 검수 | 58 (73.4%) | 1 | 20 | 42/79 (53.2%) |
| 항목별 LLM 검수 | 55 (69.6%) | 2 | 22 | 42/79 (53.2%) |

정상 확정 판정만 골라 보면 단순 검수 42/58(72.4%), 항목별 검수 42/55(76.4%)입니다. 그러나 서로 다른 문항을 제외한 값이므로 이 숫자만으로 항목별 기준의 우위를 주장할 수 없습니다.

두 방식이 모두 정상 확정 판정을 내린 **동일한 47건**에서는 단순 검수 36/47(76.6%), 항목별 검수 35/47(74.5%)입니다. 전체 79건에서 양쪽 모두 기존 판정과 일치한 것은 30건, 단순 방식만 일치한 것은 12건, 항목별 방식만 일치한 것도 12건입니다. 유의한 차이 또는 일반화 성능을 검증한 실험은 아닙니다.

공통 47건에는 기존 환각 판정이 없고 OK 24건·보정 필요 23건만 남았습니다. 조건부 Macro F1·균형 정확도·κ를 전체 79건의 세 범주 지표와 직접 비교하지 않습니다. 79건 중 유일한 기존 환각 문항 `QA-글락소-039`는 두 방식 모두 인용 검사에 실패했으며 원출력은 검토였습니다. 이번 자료로 환각 탐지 성능을 주장하지 않습니다.

## 3. 인용과 출력 형식에서 무엇이 실패했는가

42개 실패 응답의 우선 검사 결과는 인용문·위치 불일치 34개, 요약 길이 초과 8개입니다. 한 응답의 여러 문제를 전부 나타내는 배타적 오류 유형표는 아닙니다. 길이를 줄였다고 인용까지 정상이라는 뜻도 아닙니다.

전체 응답의 인용 319개를 따로 대조하면, 지정한 청크에 그대로 있는 인용은 271개, 다른 제공 청크에 있는 인용은 2개, 어떤 제공 청크에서도 문구 그대로 찾지 못한 인용은 46개입니다. 이 수치는 **인용 단위**이며 실패 응답 수와 다릅니다. 공백·줄바꿈은 정규화했지만 의역·문구 변형·위치 오류는 허용하지 않았습니다. 문구가 없다는 것이 곧 그 법률적 주장이 거짓이라는 뜻은 아닙니다.

예를 들어 두 방식이 같은 문항에서 정산방식의 위법성을 설명하는 동일한 문장을 인용처럼 출력했지만, 해당 문구는 제공된 발췌에서 찾지 못했습니다. 두 지시의 결과가 일치해도 공통된 인용 오류가 남을 수 있습니다. 따라서 프롬프트 간 합의만으로 근거를 확인했다고 처리하지 않습니다.

인용이 실제로 존재하는 경우에도 그 인용이 결론을 뒷받침하는지는 별도 문제입니다. 이번 검증 코드는 인용문 존재와 위치를 확인하며 법률적 타당성을 인증하지 않습니다.

## 4. 규칙과 결합하면 검수 대상이 어떻게 바뀌는가

기존 규칙이 적합으로 통과한 43건만 모델로 확인하는 방식을 사후 시뮬레이션했습니다. 모델이 정상 출력으로 적합을 선택할 때만 통과 후보로 남기고, 다른 판정이나 출력 검증 실패는 사람이 확인할 대상으로 보냈습니다. 모델의 부적합 의견만으로 원본을 폐기하지 않습니다.

| 방식 | 사람 확인 대상으로 보내는 수 | 기존 보정 필요·환각 47건 중 확인 대상 | 기존 OK 32건 중 확인 대상 |
| --- | ---: | ---: | ---: |
| 기존 규칙 | 36/79 | 24/47 (51.1%) | 12/32 |
| 규칙 + 단순 검수 | 62/79 | 41/47 (87.2%) | 21/32 |
| 규칙 + 항목별 검수 | 65/79 | 43/47 (91.5%) | 22/32 |
| 모두 사람 확인 | 79/79 | 47/47 (100%) | 32/32 |

항목별 기준을 결합하면 기존 규칙이 통과시킨 문항 중 29건을 더 확인하게 됩니다. 그 안에는 기존 보정 필요 19건과 OK 10건이 있습니다. 하지만 **19건 전부를 모델이 법률 오류로 발견한 것은 아닙니다.**

| 항목별 방식에서 추가 확인된 이유 | 전체 | 기존 보정 필요 | 기존 OK |
| --- | ---: | ---: | ---: |
| 정상 출력으로 검토 판정 | 15 | 9 | 6 |
| 출력 검증 실패로 확인 필요 | 14 | 10 | 4 |

단순 방식에서는 정상 검토 의견으로 추가 표시한 17건 중 보정 필요 12건·OK 5건이었고, 출력 검증 실패로 9건을 더 확인하게 했습니다. 항목별 기준의 높은 확인 대상 포함률은 검토량 증가와 출력 실패에 대한 보수적 처리의 영향도 받습니다. 이 결과만으로 더 정확하거나 비용 효율적이라고 결론내리지 않습니다.

43개 해당 요청의 관측 토큰 비용 합계는 단순 방식 약 1.74달러, 항목별 방식 약 1.96달러입니다. 실제 실험에서는 각 방식의 79건을 모두 호출했으며 위 수치는 응답을 재사용한 부분 집합 합계입니다. 사람 검수 시간·인건비·최종 수정 성공률은 측정하지 않았습니다.

## 5. 적게 확인할 때의 순서 탐색

기존 판정·신뢰도·메모를 순서 결정에 사용하지 않고, 규칙 경고 또는 모델 출력으로 순서를 정했습니다. 동점은 균등하게 선택할 때의 기대 발견 건수입니다. 문항당 확인 시간이 같다는 가정이며 비용 절감 수치가 아닙니다.

| 먼저 확인하는 수 | 기존 규칙 순서 | 항목별 모델 순서 | 두 지시의 불일치·불확실 응답 우선 | 무작위 |
| --- | ---: | ---: | ---: | ---: |
| 10 | 9.56 | 7.50 | 7.50 | 5.95 |
| 20 | 15.11 | 15.00 | 15.00 | 11.90 |
| 40 | 26.14 | 30.00 | 28.36 | 23.80 |
| 60 | 36.84 | 42.87 | 44.00 | 35.70 |

적은 수를 먼저 볼 때는 기존 규칙 순서가 더 나은 구간도 있었습니다. 모델 순서는 원문·모델 비용을 추가로 사용하며 동점 선택에 따라 결과가 달라집니다. 이는 같은 개발 표본에 대한 사후 탐색이며 CoAnnotating의 엔트로피·다운스트림 학습·비용 평가를 재현한 결과가 아닙니다. 동점별 범위는 [전체 계산](results/sonnet46_v1/evaluation.json)에 있습니다.

## 6. 구현 결과와 다음 개선점

구현한 것은 원문 검색, 기존 판정이 빠진 입력 생성, 두 프롬프트 실행, 호출 상한과 재개 처리, 인용·출력 검사, 원본 검수와의 비교, 검수 대상으로 보내는 규칙입니다. [문항별 결과 79건](results/sonnet46_v1/item_comparison79.csv)에는 기존 판정·원출력·검증 결과·추가 확인 구분을 함께 남겼습니다. [원응답 158개](results/sonnet46_v1/responses.jsonl), [실행 설정](results/sonnet46_v1/run_manifest.json), [입력 계보](input_manifest.json)도 보존했습니다.

지금 우선할 개선은 더 긴 검수 지시를 추가하는 것보다 **인용 위치·문구를 안정적으로 출력하게 하고, 자료 부족과 법률적 오류를 구분하는 것**입니다. 요약 길이 같은 형식 문제와 근거 불일치도 구분해 보완해야 합니다. 원문 검색 누락을 포함한 오류 분석과 다른 모델군 비교도 남아 있습니다. 이번에 추가 유료 재시도나 결과에 맞춘 프롬프트 재실행은 하지 않았습니다.

생산 검수기·최종 제출본·원본 판정은 변경하지 않았습니다. 기존 메모를 보고 설계한 기준을 기존 79건에서 평가했으므로 이 기록을 새 독립 시험세트로 주장하지 않습니다. 과거 검수의 전문 자격과 다중 검수자 신뢰성도 이번에 새로 검증한 것이 아닙니다. 한 모델·한 번의 생성 결과이며 모델군 편향이나 반복 실행의 변동성을 평가하지 않았습니다.

## 재현

먼저 의결서 C01.pdf~C22.pdf를 담은 기존 원문 폴더를 지정합니다. 입력과 작업용 문맥은 저장소 밖에 둘 수 있습니다.

```sh
python -m pip install -r research/judge/requirements.txt
python research/judge/prepare.py --pdf-root '/path/to/원문' --out '/path/to/judge_inputs79.jsonl'
```

기존 응답을 재분석하기만 할 때는 API 호출이 없습니다.

```sh
python research/judge/evaluate.py --run research/judge/results/sonnet46_v1 --inputs '/path/to/judge_inputs79.jsonl'
python -m unittest discover -s tests -v
```

새 모델 실험은 API 사용료가 발생합니다. 환경변수 `ANTHROPIC_API_KEY`를 설정하고 **다른 실행 폴더**를 지정합니다. 이미 저장된 실패 응답도 같은 폴더에서는 재호출하지 않습니다.

```sh
python research/judge/run.py --inputs '/path/to/judge_inputs79.jsonl' --out research/judge/local/new_run
```

입력·프롬프트·실행 코드 해시와 실제 토큰 사용량을 대조한 결과이며 가격 근거는 [공식 모델 문서](https://platform.claude.com/docs/en/models/sonnet-4-6/overview)에 연결했습니다. 검수 기준과 실험 해석은 [PROTOCOL.md](PROTOCOL.md)를 함께 참고합니다.
